这是一个基于 **Unity + XLua** 的棋牌游戏客户端（含麻将、比鸡、掼蛋、跑得快、百人牛牛五种玩法），采用 **C# 做底层框架 + Lua 写业务逻辑 + AssetBundle/Lua 双热更** 的架构。以下是各模块的实现方式分析：

---

## 一、整体架构与启动流程

**技术栈**：Unity UGUI + XLua + DOTween + DragonBones + MessagePack + LitJson + NAudio/LAME + ShareSDK（预留）

**启动链路**（单场景、多 UI 层级，非多场景切换）：

1. [Load.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Load.cs) 启动时从阿里云 OSS 拉取 `config.json` 获得 HTTP 主机和 AB 服务器地址 → 依次下载 `files.txt`（哈希清单）、`Dependencies.xml`（AB 依赖）、`MainManifest.xml`（主清单）、`GameManifest.xml`（各游戏清单），对比本地哈希增量更新主 AB
2. [Login.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Login.cs) HTTP 登录（图形验证码 + 账号密码 AES 加密），token 加密存 PlayerPrefs 免登录
3. [GameManager.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Game/GameManager.cs) 加载大厅 prefab → [GameEntry.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/GameEntry.cs) 按需下载游戏子包 → HTTP 获取游戏服务器地址 → TCP 进房间

[Client.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Client.cs) 是全局驱动器，每帧顺序驱动：主线程调度器 → Lua GC（`LuaEnv.Tick` 每秒）→ 消息队列处理 → 网络心跳检测 → 定时器 → AB 自动卸载。**全部管理器为饿汉式单例**。

UI 层级通过父节点划分：`HallPanel`（App 大厅）/ `GamePanel/Hall`（游戏大厅）/ `GamePanel/Game`（游戏房间）/ `TipPanel`、`PromptPanel`（全局提示层）。

## 二、Lua 热更新（C#/Lua 混合架构）

- [LuaManager.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Lua/LuaManager.cs)：创建全局唯一 `LuaEnv`，注册自定义 loader 和 `rapidjson` 内置库
- [LuaScriptLoader.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Lua/LuaScriptLoader.cs)：编辑器下从 `Resources/LuaScripts`（`.lua.txt`）读取，真机从 `luascripts.ab` 加载（该 AB 永不卸载）
- [LuaBehaviour.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Lua/LuaBehaviour.cs)：核心粘合层。每个 UI prefab 挂一个此脚本指定 Lua 模块名，`require` 后把 LuaTable `Cast` 成 `ILuaBehaviour` 接口，将 Awake/Start/Update/OnDestroy 生命周期转发进 Lua；每个脚本独立 scope table（元表 `__index` 指向 global）防止全局变量冲突；支持 Injection 数组往 Lua 注入 GameObject
- [LuaMessageBehaviour.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Lua/LuaMessageBehaviour.cs)：Lua 模块声明 `messages = "MsgA,MsgB,..."` 字符串即自动注册为消息处理器；断线/重连事件也转发给 Lua
- 桥接层：[LuaUGUI.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Lua/LuaUGUI.cs)（按钮绑定/文本读写等 UGUI 静态封装）、[LuaDOTween.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Lua/LuaDOTween.cs)（补间动画封装给 Lua 调用）

业务逻辑几乎全在 Lua：如 [Room.lua](file:///d:/work/QP_client/Assets/NiuMa/Resources/LuaScripts/Game/Mahjong/Room.lua.txt)（麻将房间，1600+ 行）。

## 三、网络模块（HTTP + TCP 双通道）

**HTTP 通道**（[HttpRequester.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Game/HttpRequester.cs)）：
- 封装 `UnityWebRequest` 协程版 Get/Post/下载图片/下载文件，用于登录、玩家信息、进房申请、心跳（30 秒 `/player/heartbeat`）
- 鉴权：`PLAYER-AUTHORIZATION` 请求头携带 token，401 统一弹窗回登录

**TCP 长连接**（[Connection.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Network/Connection.cs) + [NetworkManager.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Network/NetworkManager.cs)）：
- .NET `Socket` 异步 API（`BeginConnect/BeginReceive/BeginSend`），非阻塞 + NoDelay，8KB 接收缓冲、4MB 解包缓冲
- **协议格式**：`MsgWrapper { msgType: 字符串, msgPack: Base64(MessagePack二进制) }`，用 MessagePack 自描述长度实现**粘包/半包拆分**（双缓冲交换），Lua 侧消息则是 JSON → MessagePack 打包
- **消息分发**：网络线程推入线程安全队列 → 主线程 `MsgManager.HandleMessages` 取出 → 先走 C# 强类型消息工厂（工厂注册于 [MsgManager.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Message/MsgManager.cs)），否则反序列化为 JSON 责任链分发给 Lua
- **心跳**：每 5 秒发 `MsgHeartbeat`，超 5 秒未回执即判死链
- **断线重连**：最多重试 4 次（每次间隔 5 秒），重连成功后广播 `IReconnectHandler` 列表通知各模块恢复状态
- **防重放签名**：MD5(`playerId & timestamp & nonce & secret`)，nonce 为 10 位随机码并做 60 秒去重；签名失效自动经 HTTP 刷新密钥

## 四、语音模块（录 → 编 → 传 → 解 → 播 全链路自研）

- **录音触发**：[VoiceRecorder.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Audio/VoiceRecorder.cs) UGUI 按下/抬起/滑出事件，滑出取消发送，强制最短 500ms 防快速点击崩溃
- **录音**：[VoiceManager.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Audio/VoiceManager.cs) 用 `Microphone.Start`（11.025kHz、最长 60 秒）
- **编码**：[AudioClipConverter.cs](file:///d:/work/QP_client/Assets/Lame/AudioClipConverter.cs) 取 AudioClip 采样数据手写 PCM，经 **NAudio + LAME 编码为 MP3**（ABR_128）
- **传输**：不走语音服务器，直接读 MP3 文件转 **Base64 塞进 TCP 消息**（`MsgVoiceClient`）发送；收到 `MsgVoiceServer` 落地为本地 MP3 文件再转 `MsgPlayerVoice` 交给 Lua
- **播放**：MP3 → NAudio 解码为 WAV → `UnityWebRequestMultimedia` 加载 AudioClip → AudioSource 播放，**串行播放队列**，播完即删临时文件
- 录音期间 AudioManager 自动将背景乐与音效临时静音

## 五、音乐音效

- [AudioManager.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Audio/AudioManager.cs)：**1 个背景音乐 AudioSource**（挂在 Main Camera）+ **多个 [SoundEffect.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Audio/SoundEffect.cs) 组件**（各持一列表 AudioSource，如每个座位独立音源，实现“按座位方向出牌音效”）
- 音乐/音效分离的音量与静音，`PlayerPrefs` 持久化；音效资源由 Lua 端 [AudioControl.lua](file:///d:/work/QP_client/Assets/NiuMa/Resources/LuaScripts/Game/Mahjong/AudioControl.lua.txt) 按 clip 名用 Lua table 缓存，从 `sounds/mahjong.ab` 等 AB 包加载

## 六、画面表现

- **UI 框架**：无传统 WindowManager 窗口栈，采用 **prefab + LuaBehaviour 组合**，C# 只做薄壳（找节点、加载 prefab），逻辑在 Lua；对话框 prefab 动态 Instantiate 到对应层
- **动画**：DOTween（经 LuaDOTween 供 Lua 调用）做位移/缩放补间（出牌、飞牌）；Unity Animator 做等待转圈；[UGUISpriteAnimation](file:///d:/work/QP_client/Assets/NiuMa/Scripts/UI/UGUISpriteAnimation.cs) 序列帧动画
- **骨骼动画**：DragonBones，[DragonBoneControl.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/DragonBone/DragonBoneControl.cs) 封装动画事件监听（START/COMPLETE/FRAME_EVENT 等）回调给上层
- **麻将渲染**：纯 2D UGUI，`Image + Sprite` 图集（[MahjongBrick.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Mahjong/MahjongBrick.cs) 实现牌的拖拽出牌（位移>30px 判定为出牌）与点击，通过 `IMahjongPaver` 接口直接回调 Lua 的 Paver 模块）；[BezierPath](file:///d:/work/QP_client/Assets/NiuMa/Scripts/UI/BezierPath.cs) 贝塞尔曲线用于飞牌轨迹
- **特效与自定义 Shader**：震屏 ShakeScreen、船特效 EffectShip、`MyUIMask` 头像圆形遮罩 Shader、截图保存相册（[Screenshot2PhotoAlbum](file:///d:/work/QP_client/Assets/NiuMa/Scripts/UI/Screenshot2PhotoAlbum.cs)）

## 七、资源与热更管理

- [ResourceManager.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Game/ResourceManager.cs)：编辑器走 `Resources.Load`；真机走 AB（哈希对比增量更新 + XML 依赖表**递归加载依赖** + **30 秒未访问自动 `Unload(false)`**，Lua AB 除外）
- 游戏按**子包**划分（`mahjong/hall.ab`、`biji/room.ab`…），点击游戏时才下载对应更新包（[GameManifest.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Game/GameManifest.cs)）

## 八、其他支撑模块

- **定时器**：GameManager 内基于 LinkedList 按到期时间有序插入的定时器队列（Lua 可经 `AddTimer` 使用）
- **GPS 定位**：[Client.cs](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Client.cs) 每 5 分钟采集一次经纬度上报服务器（棋牌防作弊常用）
- **多线程调度**：[UnityMainThreadDispatcher](file:///d:/work/QP_client/Assets/NiuMa/Scripts/Core/UnityMainThreadDispatcher.cs) 把网络线程的日志/回调转回主线程（IL2CPP 限制）

---

**总结一句话**：这是一个典型的“**C# 引擎层 + Lua 逻辑层**”棋牌客户端——网络（TCP/MessagePack + HTTP/Json 双通道）、语音（LAME MP3 + Base64 内嵌传输）、音频（分区 AudioSource）、热更（AB 哈希增量 + Lua 脚本包）等基础设施用 C# 实现并以单例暴露给 Lua，而五种游戏的全部玩法 UI 逻辑用 Lua 编写，通过消息驱动（服务器权威 + 客户端表现）的方式运转。
